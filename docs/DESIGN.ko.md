# Thread Atlas 작업 지도와 메인 대화 설계

여러 창에 일을 맡긴 사람이 “어제 로그인 버그 보던 게 어디까지 됐지?”라고 묻고, 답을 확인한 자리에서 “그럼 테스트부터 돌려줘”라고 이어 갈 수 있는 로컬 앱이다. 기존 ChatGPT, Claude, Codex 대화가 작업의 원본이다. 앱은 원본의 위치와 최근 상태를 기억하고, 사용자가 의도한 곳으로 후속 요청을 전달한다.

[English design](./DESIGN.md) · [한국어 화면 시안](./THREAD-ATLAS.html#ko) · [한국어 미리보기](./THREAD-ATLAS.ko.png)

영어가 기본 언어다. 사용자가 사이드바에서 한국어를 선택하면 UI와 가상 예시를 한국어로 표시한다. 사용자가 직접 쓴 문장과 원본 대화는 작성된 언어를 유지한다.

## 첫 사용 장면

1. 사용자가 메인 창에 “어제 로그인 버그 보던 거 어디까지 됐지?”라고 입력한다.
2. 지도에서 **인증 개편 › 토큰 갱신 오류** 카드가 강조된다. 접힌 프로젝트는 펼치고, 다른 프로젝트의 배치와 현재 확대율은 유지한다.
3. 메인 창은 “수정이 끝났고 회귀 테스트 실행을 기다리고 있습니다”라고 답한다. 바로 아래에 근거가 된 **Codex 원문**, 원본 작성 시각, 원문 보기 동작이 붙는다. 정보가 오래됐으면 동기화 시각도 표시한다.
4. 사용자가 “그럼 테스트부터 돌려줘”라고 쓰면 입력창 위에 **인증 개편 › 토큰 갱신 오류 · Codex**가 표시된다. 보내기를 누르면 그 원본 스레드가 후속 메시지를 받는다.
5. 그 사이 Claude에서 환불 정책 검토가 끝나면 받은 답변에 새 항목이 생긴다. 사용자는 쓰던 문장을 마저 보내거나, 새 알림의 ‘이어서 답장’을 선택해 명시적으로 대상을 바꿀 수 있다.

## 한 화면에 둘 관계

| 영역 | 사용자가 결정하는 것 | 화면 동작 |
| --- | --- | --- |
| 왼쪽 탐색 | 어느 범위의 일을 볼지 | 작업 지도, 받은 답변, 숨김, 프로젝트 목록을 제공한다. 미확인 수는 새 답변의 실제 도착을 반영한다. |
| 가운데 지도 | 어떤 대화가 어느 일에 속하는지 | 프로젝트와 소속 스레드를 선으로 잇는다. 같은 프로젝트 안에 ChatGPT 기획, Claude 리뷰, Codex 구현을 함께 둔다. 서비스와 계정은 카드에 표시한다. 선은 소속 관계를 뜻한다. |
| 오른쪽 메인 대화 | 어떤 일을 찾고 어디에 다음 요청을 보낼지 | 찾은 카드, 최신 답변 원문, 후속 요청의 목적지가 서로 대응한다. 현재 대상에는 지도와 입력창에 같은 표시를 쓴다. |
| 받은 답변 | 지금 내 주의가 필요한 일이 무엇인지 | 답변 완료와 입력 요청을 도착순으로 보여 준다. ‘원문 보기’는 읽기, ‘이어서 답장’은 대상 변경이다. 두 동작의 효과가 다르다. |

처음 연결한 세션은 원래 프로젝트나 작업 폴더에 배치하고, 소속을 알 수 없으면 ‘미분류’에 둔다. 이름이 서로 비슷해도 계정·워크스페이스·원본 ID로 구별한다. 세션이 수십 개가 되면 프로젝트를 접어 **세션 수, 미확인 수, 답변 대기 수**만 남긴다. 새 답변이 와도 지도에서 카드가 순서대로 재정렬되지 않으므로 사용자가 기억한 위치를 다시 찾을 수 있다.

## 드래그가 뜻하는 것

| 놓는 위치 | 결과 | 드래그 외 조작 |
| --- | --- | --- |
| 다른 프로젝트 | 해당 세션의 로컬 소속 변경 | 카드 상세의 프로젝트 선택 |
| 같은 프로젝트의 카드 앞 | 같은 가지 안에서 순서 변경 | 제품판에서는 키보드 순서 이동도 제공 |
| 메인 입력창 | 전송 대상을 고정하고 입력에 포커스 | 카드 상세의 ‘메인 창 대상으로 지정’ |
| 숨김 | 지도, 알림, 자동 추적 후보에서 제외 | 카드 상세의 ‘숨기기’. 숨김 목록의 ‘복구’로 원래 그룹에 다시 표시 |

‘안 보고 싶다’의 기본 동작은 이 앱에서 숨기기다. 소속 변경과 숨김은 다시 동기화해도 유지한다. 원본 서비스 자체에서 대화를 영구 삭제하는 동작은 별도의 사용자 의도가 필요하다.

## 질문과 발신을 구분하는 규칙

| 사용자 입력 | 근거와 동작 |
| --- | --- |
| “로그인 버그 어디까지 됐지?” | 전체 로컬 메시지 기록을 검색한다. 일치한 메시지와 최신 원문 답변을 각각 시각과 함께 보여 준다. 외부 요청은 생기지 않는다. |
| “그럼 테스트부터 돌려줘” | 방금 찾은 작업을 잇는 지시다. 같은 원본의 전송 가능 상태를 확인하고 입력창에 목적지를 표시한다. |
| “결제 재시도는 최대 3회로 해줘” | 로그인 작업을 보고 있었어도 ‘결제 재시도’가 가리키는 새 대상을 찾는다. 서비스가 달라져도 본문과 기존 맥락은 해당 원본에만 전달한다. |
| “왜 3회인지 Claude에 물어봐줘” | 외부에 질문을 보내 달라는 지시다. 서비스·계정 범위와 주제를 모두 단서로 사용한다. 해당 범위에 후보가 여럿이면 마지막 메시지를 함께 보여준다. |
| “진행해” | 직전에 명시적으로 정한 대상이 있으면 이어 간다. 없으면 유력한 후보의 프로젝트, 서비스, 마지막 질문을 제시한다. 사용자의 선택이 발신을 확정한다. |
| “내 답변 기다리는 일 보여줘” | 여러 원본의 대기 항목을 모아 보여 준다. 사용자가 하나를 골라 이어 가기 전에는 단일 목적지가 생기지 않는다. |

지도에서 카드를 살펴보는 동작, 알림이 도착하는 동작, 원문을 보는 동작과 **메시지 목적지 지정**을 구별한다. 작성 중에는 대상 ID를 초안에 묶는다. 다른 대상을 명시한 새 메시지에는 전송 전에 바뀐 목적지를 보여 준다. 목적지가 읽기 전용이면 직접 답장을 지원하는 다른 세션으로 자동 우회하지 않는다. 원본 링크와 작성 문장 복사를 제공하고 ‘원본 직접 전송’ 성공률은 별도로 집계한다.

## 연결 범위와 알림

각 연결의 기능을 **발견, 이력 읽기, 새 답변 감지, 원본 발신**으로 각각 기록한다. 연결 화면에 계정별로 발견한 세션 수, 실시간 추적 수, 직접 답장 가능 수, 마지막 확인 시각을 보여 준다. 웹 탭을 닫거나 연결이 끊긴 기간에는 ‘마지막 확인’과 ‘다시 연결’을 제공한다. 활동을 관찰할 수 없는 상태를 ‘작업 완료’로 해석하면 안 된다.

| 출처 | 사용할 경로 | 제품에 표시하기 전 검증 |
| --- | --- | --- |
| Codex 로컬 | App Server의 목록·이력·재개·턴 이벤트를 사용한다. | 데스크톱과 CLI에서 각각 시작한 기존 작업이 열거되는지, 다른 창에 온 답변이 포착되는지, 후속 메시지가 같은 원본 ID에 한 번만 기록되는지 본다. [Codex App Server](https://developers.openai.com/codex/app-server) |
| Claude Code 로컬 | 세션 ID로 목록과 이력을 읽고, 재개와 훅을 연결한다. | 종료된 세션의 재개와 현재 터미널에서 진행 중인 세션의 입력을 따로 확인한다. 이미 실행 중인 세션에서 두 실행 주체가 같은 기록에 쓰는 일을 방지한다. [Claude Code 세션](https://code.claude.com/docs/en/agent-sdk/sessions) · [훅](https://code.claude.com/docs/en/hooks) |
| 개인용 ChatGPT·Claude 일반 대화 | 내보내기로 과거 기록을 수집하고, 사용자가 연결한 브라우저 탭의 갱신·답장 가능성을 시험한다. | 내보내기는 특정 시점의 기록이다. 개인용 기존 웹 대화를 모두 구독하고 발신하는 공개 API는 확인되지 않았다. 계정 전환, 백그라운드 탭, 닫은 탭, 재연결을 구분해 검증한 범위만 표시한다. [ChatGPT 내보내기](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data) · [Claude 내보내기](https://support.claude.com/en/articles/9450526-export-your-claude-data) |

답변 완료와 사용자 입력 요청은 기본적으로 앱 받은 답변과 macOS 알림으로 한 번씩 전달한다. 앱 창을 닫아도 메뉴 막대 수집기가 실행 중이면 계속 받는다. 잠자기 후에는 마지막 확인 지점부터 누락을 대조한다. 휴대폰 메시지는 사용자가 고른 채널로 연결하고, 프로젝트·제목만 보낼지 최신 답변 일부까지 보낼지 선택하게 한다.

## 구현 구조와 순서

로컬 데스크톱 앱과 SQLite에 지도 배치, 원본 식별자, 메시지 출처, 읽음 상태, 발신 기록을 둔다. 메인 창의 찾기 요청은 로컬 검색이 처리하고, 발신 요청은 스레드 ID와 초안 ID를 갖는 발신 대기열을 거친다. 연결별로 접수, 원본 반영, 답변 도착을 구분한다. 전송 직후 연결이 끊긴 요청은 원본과 대조하기 전 중복 발신하지 않는다. 브라우저나 터미널을 조작하는 에이전트는 커넥터 후보 중 하나다. 동일 계정·동일 원본과 전송 결과를 반복해서 식별할 수 있는지가 채택 기준이다.

1. **세로로 하나의 흐름을 완성한다.** 작은 지도와 메인 창을 함께 만든다. 기존 로컬 세션 두 개에서 ‘찾기 → 최신 원문 → 후속 메시지 → 같은 원본의 답변’까지 시연한다. 동시에 두 개인용 웹 서비스에서 원본 왕복과 닫은 탭의 동작을 시험한다.
2. **여러 세션에서 판단을 검증한다.** 이름이 비슷한 세션 20개를 두고, 영어와 한국어 각각에 대해 제목이나 답장 버튼을 지정하지 않은 발신 요청 50개를 평가한다. 제안 기준은 올바른 자동 전달 40개 이상, 시험 중 오발송 0개다. 모호한 10개, 조회 전용 질문, 외부에 질문해 달라는 지시, 새 알림이 들어오는 도중의 초안을 별도로 평가한다.
3. **지도를 크게 써도 방향을 잃지 않게 한다.** 100개 세션으로 그룹 접기, 검색 후 강조, 드래그, 숨김·복구, 읽음 상태의 재시작 복원을 검증한다. 재연결 시 과거 답변이 새 알림으로 한꺼번에 쏟아지지 않아야 한다.
4. **서비스별 지원 상태와 함께 배포한다.** 실제 테스트 계정에서 원본 왕복을 확인한 연결만 직접 전송으로 표시한다. 웹 연결이 읽기 전용으로 남으면 ‘모든 웹 대화를 메인 창에서 이어 가기’는 미완료로 남긴다. 저장소에는 코드, 문서, 가상 세션을 넣고 실제 대화와 인증 정보는 로컬 앱 데이터에 보관한다.

## 이번 시안의 범위

HTML 파일은 가상 프로젝트 3개와 세션 6개로 위 흐름을 체험하는 클릭 가능한 디자인 시안이다. 예시 주제에 맞춰 질문, 후보 선택, 후속 요청, 가상 답변 도착, 원문 보기, 카드 이동과 숨김을 시연한다. 실제 계정 연결, 자연어 라우팅의 정확도, 원본 전송, OS·휴대폰 알림은 제품 구현에서 검증할 항목이다. 시안에서 변경한 상태는 새로고침하면 초기화된다.
